# 演示场景与截图

README 截图取自实际页面。范围结果、会议结论与手机结果使用同一次真实百炼输出，不使用手写结果替代。

## 活动上线

输入是 [`demoInput`](../src/lib/demo.ts)：5 人、10 个工作日、12 条需求，成功标准为“商家能报名、运营能审核、活动能上线”。

2026-09-08 发布前本地生产验证：

- 模型：`qwen3.6-plus`，1 次模型调用，约 16.9 秒，2772 tokens。
- 可用产能 35 人天，Must 3 条、合计 6 人天：商家报名表、运营审核、活动上线开关。
- 四组分别为 Must 3 条、Should 3 条、Could 1 条、Won’t 5 条。
- 目标可达性、必要项、明确依赖、非承诺分类、硬规则、可见结果和复制等 13 项断言通过。
- 同一结果检查 1440、1280、1100、768、390、320px 的五个工作视图，无横向溢出。

耗时是单次观测，不是服务承诺；Token 用量不是账单金额。模型在新输入或再次运行时可能产生不同建议。

## 建议体验顺序

1. 用示例生成结果，查看三条 Must 如何覆盖三个目标。
2. 将人数改为 1、工作日改为 3，查看目标不可达时的空承诺与部分工作候选。
3. 回到需求清单，明确排除“运营审核”，查看它与上线目标之间的冲突。
4. 核对原文依据，编辑并复制会议结论。

公开 Demo 受共享额度和按 IP 的限流保护，连续修改生成时可能需要等待。完整模型矩阵与浏览器负例需按[验证说明](testing.md)单独运行，不能从上述单次演示推断全部输入都已通过。

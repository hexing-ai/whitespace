## 建议体验顺序

1. 用示例生成结果，查看三条 Must 如何覆盖三个目标。
2. 将人数改为 1、工作日改为 3，查看目标不可达时的空承诺与部分工作候选。
3. 回到需求清单，明确排除“运营审核”，查看它与上线目标之间的冲突。
4. 核对原文依据，编辑并复制会议结论。

公开 Demo 受共享额度和按 IP 的限流保护，连续修改生成时可能需要等待。完整模型矩阵与浏览器负例需按[验证说明](testing.md)单独运行，不能从上述单次演示推断全部输入都已通过。

发布时，本机网络访问 Vercel 域名受到连接重置影响，线上验收通过 GitHub Actions 的独立网络完成。未验证所有地区网络可达性、Safari 和实体手机；响应式检查采用 Chromium 视口模拟。
